# AI 麻将助手 Prototype

手机优先的静态 PWA 原型。站点由 GitHub Actions 将 `dist/` 发布到 GitHub Pages。

## iPhone 使用

1. 在 iPhone 的 Safari 中打开 GitHub Pages 地址。
2. 点“分享”，选择“添加到主屏幕”。
3. 从主屏幕图标打开后，按设置向导允许摄像头与麦克风，并测试播报。

站点界面、样本牌面模板与 Mock 牌局在首次打开并缓存后可以离线使用。浏览器语音识别服务是否能离线工作取决于 iOS 版本与系统实现；无法识别时可使用页面文字输入。摄像头、麦克风和屏幕常亮能力也取决于当前 iOS 浏览器支持与系统权限。

## 本地运行

在项目目录运行 `node scripts/dev-server.mjs`，打开 `http://127.0.0.1:4173/`。真机访问摄像头和麦克风需要 HTTPS，建议用已发布的 GitHub Pages 地址测试。

主要模块位于：

- `dist/assets/services/`：摄像头、真实静态牌面测试、语音与 TTS 音频锁
- `dist/assets/core/`：事件存储、牌局状态机、规则与决策引擎
- `dist/assets/app.js`：页面渲染与交互编排

GitHub Pages 的子路径由应用自动推导，页面、脚本、图标与 Service Worker 都使用相对路径。修改后推送到 `main` 即会触发发布。

## 当前规则与决策范围

默认规则为用户提供的 `GD-SZ-DEFENSE-V1`（广东麻将防点炮训练配置），不是通用的“广东麻将”规则。使用 136 张牌、无花、不能吃；鸡胡 2 分且仅能自摸；允许一炮多响。普通四面子一将、七小对／豪七、十三幺及若干明确牌型由确定性算法判定。牌型是否叠加、封顶、庄闲和自摸支付、杠分、抢杠胡、包牌精确结算与多人碰杠优先级未在附件中定义，网站不计算总分。

建议引擎对所有可打牌枚举，并计算向听、有效摸牌种类及公开信息下的未见张数。默认“防守优先”使用附件里的旧版轻量风险公式对候选作**相对排序**；它未经真实对局概率校准，也不知道对手暗手，不能作为真实点炮概率或绝对安全判断。碰／明杠可能性与荣和风险分开记录。同牌旧牌河只做软修正，只有明确且仍有效的玩家／牌／动作响应锁才视为硬限制。手切会解除该玩家旧锁，摸切可保留。

## 真实牌面测试的边界

首页“识别测试”可从后置摄像头拍一帧或选本机照片；设置向导也可用真实照片生成初始 13 张手牌。页面会显示每张裁剪图，低把握牌留为“待确认”，必须逐张核对并主动确认后才能开局。用户手动纠正的牌面特征仅保存在当前浏览器本机，以帮助后续同样式照片匹配。上传的完整照片不会提交到 GitHub Pages 或其他服务；公开仓库仅包含从三张授权样本生成的约 43 KB 牌面图块模板。

这还是**牌面测试版，不是可靠的实时麻将识别**。模板覆盖三张样本里出现的牌，并未覆盖全部 34 种牌或更多麻将牌外观。用参与模板制作的三张原图回测会得到 39/39，但这只验证了处理链路，不是独立准确率；按“整张照片留出”交叉检查时，严格阈值下只有 2/39 张被自动接受（均为八万），其余需要人工确认。当前牌位数按用户选择的 13/14 张分割，并非独立数牌；摄像头连续监测、自动摸牌和自动弃牌尚未接入，牌局中的相关按钮仍明确标为模拟。不能把这版识别结果直接用于实战。iPhone 真机的权限、拍摄角度、后台保持与语音能力仍需实际设备验证。
